# dzenc

**简单、可靠、能直接给不懂技术的人用的文件加密工具。**
中文图形界面，双击即用；命令行同样可用。

加密方案：**Argon2id** 密钥派生 + **AES-256-GCM** 分块认证加密。

> A simple file encryption tool with a Chinese GUI. Argon2id + AES-256-GCM,
> single-file Windows executable, no Python required for end users.

---

## 为什么要再造一个轮子

zip / 7z 的"加密压缩包"有三个常见毛病：

1. **没人管口令强度。** 用户随手打一个 6 位数字，AES-256 也救不了——密钥空间只有一百万，
   显卡跑几分钟就撞开了。算法的强度被口令的熵拖垮。
2. **普通用户不会用。** 界面是英文的、要选加密算法、要理解"加密文件名"这种选项。
3. **口令怎么给对方，工具从不管。** 于是最常见的结果是：密文发微信、口令也发微信，
   等于没加密。

这个工具针对这三点做了取舍。

---

## 特性

- **单文件 exe**，目标机器不需要装 Python，也不需要联网
- **中文界面**，三步走完：拖文件 → 输口令 → 点按钮
- **自动判断加解密**：按 `.enc` 后缀自动切换模式，使用者不需要理解概念
- **实时口令强度提示**，并提供一键生成强口令（自动复制到剪贴板）
- **后台线程处理**，加密大文件时界面不卡死
- **同名 `.enc` 文件**，解密时自动去掉后缀还原
- 附赠命令行模式，方便脚本批处理

## 快速开始

### 图形界面

从 [Releases](../../releases) 下载 `文件加密工具.exe`，双击运行。

1. 把文件拖进窗口，或点击窗口选择文件
2. 输入口令（加密时需输两遍）
3. 点按钮

加密产生 `原文件名.enc`；把 `.enc` 发给对方，对方用同样步骤解密。

> Windows 首次运行可能弹「Windows 已保护你的电脑」蓝色提示框——
> 因为程序没有购买微软代码签名证书。点「更多信息」→「仍要运行」即可。

### 命令行

```bash
python dzenc.py encrypt 报告.docx -p 我的口令
python dzenc.py decrypt 报告.docx.enc -p 我的口令 -o 还原.docx
```

不带参数就是图形界面。打包后的 exe 同样支持这套参数：

```bash
文件加密工具.exe encrypt 报告.docx -p 我的口令
```

> `-p` 后面直接写口令会留在命令历史里。敏感场景请省略 `-p`，
> 程序会交互式询问。

## 安全设计

### 三层防护

| 层 | 机制 | 解决什么 |
|---|---|---|
| 密钥派生 | **Argon2id**，64 MiB 内存 / 3 轮 / 4 并行 | 内存硬函数，每次尝试强制占用 64 MiB，显卡并行暴破被内存带宽卡死 |
| 加密算法 | **AES-256-GCM** | 认证加密。密文改动任意一个比特，解密直接失败，不会解出乱码蒙混过关 |
| 分块绑定 | 块序号与末块标志写入 AAD | 防重排、防截断——这是自写加密最常翻车的地方 |

### 文件格式

```
┌──────────┬─────────────────────────────────────────┐
│ 偏移 0   │ Magic  b"DZENC\x01"             (6 字节) │
│ 偏移 6   │ memory_cost  uint32 小端          (4 字节) │
│ 偏移 10  │ iterations   uint32 小端          (4 字节) │
│ 偏移 14  │ lanes        uint32 小端          (4 字节) │
│ 偏移 18  │ salt                             (16 字节)│
├──────────┴─────────────────────────────────────────┤
│ 数据块 × N（顺序排列）：                              │
│   nonce (12) │ flags (1) │ len (4) │ 密文+tag (len)  │
│   flags bit0 = 1 表示这是最后一块                     │
└─────────────────────────────────────────────────────┘
```

KDF 参数存在文件头而不是写死在代码里——将来调高强度时，**旧文件仍然能解开**。

### 分块细节

文件按 1 MiB 分块，每块用独立的随机 nonce。每块参与认证的 AAD 是
`(块序号, 是否末块)` 两个字段：

- **防重排**：块序号变了，AAD 对不上，GCM 校验失败
- **防截断**：末块标志为 1 的块被删掉后，新的"最后一块"标志为 0，
  解密读到文件末尾也没等到末块，直接报错

## 威胁模型

**这个工具能防什么、不能防什么，说清楚比什么都重要。**

### 能防

- 密文在传输途中（微信／网盘／邮件／局域网）被第三方拿到 —— 没有口令打不开
- 密文被篡改或损坏 —— 认证加密直接拒绝，不会解出错误内容
- 弱口令被暴力破解 —— Argon2id 把单次尝试的成本抬到 64 MiB 内存，
  但**仍强烈建议 12 位以上口令**

### 不能防

- **口令和密文走同一条通道。** 密文发微信、口令也发微信，等于白加密。
  口令请当面说或打电话——这是整套流程里最容易出错的一步，工具管不了。
- 文件被解密之后的事。
- **被胁迫交出口令。** 本工具没有可否认性设计（没有 VeraCrypt 那种隐藏卷），
  交出正确口令就等于交出内容。
- 键盘记录器、内存取证、屏幕截图等端点侧攻击。
- 文件名的泄露：输出文件名默认保留原名（`工资表.xlsx.enc`），
  这暴露了"存在这样一份文件"。

## 测试

```bash
python test_dzenc.py      # 核心引擎：往返、篡改、截断、重排、随机性
python test_gui.py        # 图形界面全流程 + 自动截图
python test_exe_e2e.py    # 打包后的 exe 端到端（需先 build）
python test_exe.py        # exe 独立启动验证（Windows）
```

`test_dzenc.py` 覆盖 6 种输入长度（含空文件、正好 1 MiB 的分块边界），
并逐项验证三种攻击场景：翻转 1 bit、截断末块、重排数据块。

性能参考：100 MB 文件加密约 0.22 秒（445 MB/s），内存占用恒定
（流式分块，不随文件大小增长）。

## 构建

```bash
pip install pyinstaller tkinterdnd2
python build.py           # 产物在 dist/文件加密工具.exe
```

Windows 上也可以直接双击 `build.bat`。

依赖：`cryptography`（唯一的运行时依赖）、`tkinterdnd2`（拖拽，可选——
缺失时自动退回"点击选择文件"）。
